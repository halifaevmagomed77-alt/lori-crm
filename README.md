# Lori CRM

CRM свадебного салона Lori — электронная версия бумажного журнала салона. Платья только сдаются в аренду.

Сейчас это **прототип**: база пустая, «из коробки».

## Общая демо-база

Чтобы демо было одинаковым на всех устройствах (ноутбук разработчика, телефон владельца, планшет в салоне), база и фото хранятся в **Vercel Blob** (приватные файлы):

1. Vercel → проект lori-crm → **Storage** → Create → **Blob** (Private) → подключить к проекту (появится `BLOB_STORE_ID`, доступ по OIDC).
2. Пересобрать проект (Deployments → Redeploy).

Как работает: при открытии CRM берёт общую базу с сервера, после каждого изменения через ~1 с отправляет её обратно (сжатой). Если базу одновременно изменили с другого устройства, свои ещё не сохранённые изменения накладываются на свежую версию — ничего не теряется. Свежее подтягивается при возврате на вкладку и раз в 10 минут, если экран открыт; вручную — «Обновить» на плашке «Демо». Фото платьев и снимки табеля тоже уходят на сервер.

Без хранилища (нет ни `BLOB_STORE_ID`, ни `BLOB_READ_WRITE_TOKEN`) или локально всё работает как раньше — только в браузере; на плашке «Демо» написано «Данные только на этом устройстве». Для локальной проверки синхронизации: `LORI_LOCAL_SYNC=1 npm run dev` (файлы во временной папке).

Ограничения бесплатного тарифа Vercel Blob: 2 000 записей и 10 000 чтений в месяц — для демо хватает, для работы салона нет. Демо-база доступна всем, у кого есть ссылка, — только тестовые данные. Рабочая версия — отдельный сервер в России (см. ниже).

Владелец меняет имена, логины и пароли и добавляет консультантов (до 30) в «Отчёты → Сотрудники». Там же — «Заполнить примером» (год работы салона для просмотра отчётов) и «Очистить все данные».

Внизу каждой страницы плашка «Демо» и кнопка «Замечание»: текст с разделом и ролью копируется и открывается Telegram @halifaevmg.

Рассчитано на телефон: пять вкладок внизу экрана.

## Разделы

1. **Журнал** — дата в самом верху, строки «Зашли, Примерка, Возвратные, Запись, Отказ, Выдача, Приёмка, Химчистка», у владельца отдельным цветом «Залог, Аренда, Доп, Штрафы» за день; итог по консультантам «встретила / записала, %».
2. **Книга записей** — карточки записей, две на экран телефона; поиск по имени, телефону, платью и № договора, фильтры.
   - У **консультанта** — свой экран, как страница тетради: сверху дата и «Имя И.О.», кнопка «Новая запись» и поля: ФИО невесты, телефон, дата свадьбы, платье из базы, сумма, залог (наличные / банк), доп, штраф с причиной, № договора аренды, № договора на залог, комментарий → «Отправить на подтверждение». Ниже «Сегодня записали» и все записи с поиском.
   - После подтверждения владельцем в записи красная строка: «Залог 30 т.р / ВТБ / 29.10 / подтверждён», «остаток 90 т.р».
   - Защита: платье на занятые даты, телефон уже в базе, повтор № договора, дата в прошлом.
   - Возвратная невеста: при вводе фамилии (от 3 букв) или цифр телефона (от 4) сразу показываются совпадения из базы — когда была, что мерила, её консультант, есть ли запись. «Это она» → метка «Возвратная · N-й визит». Визит и запись засчитываются её консультанту; если обслужила другая — это видно в карточке («обслужила …»). В отчётах: возвратные и сколько из них записались, по салону и по каждому консультанту.
   - Владелец подтверждает в «Книге записей» — блок «Ждут подтверждения».
3. **Редактор** (администратор и владелец) — невесты, платья, химчистка. При поступлении платья владелец отмечает сразу все привезённые размеры модели и количество по каждому — каждый экземпляр заводится отдельным платьем (у каждого своя занятость по датам), фото и цены общие. У консультанта «Редактора» нет: невесты и платья (только просмотр) — вкладки «Книги записей»; после сохранения консультант меняет только комментарий.
4. **Табель** — у владельца и администратора таблица «пришла / ушла» по дням и итоги за 30 дней; время можно поправить вручную.
5. **Отчёты** (владелец) — построчно «Зашли, Примерка, Возвратные, Запись, Отказ, Выдано» и деньги отдельным цветом, консультанты, модели, отказы, штрафы, поставщики; вкладка «Сотрудники».

## Табель на планшете — `/tabel`

Отдельный экран для планшета в салоне, без меню CRM. Открыт всегда — без ежедневного открытия и закрытия и без паролей сотрудников.

1. Сотрудник нажимает на своё имя и выбирает «Пришла», «Ушла» или «Выходной». Через несколько секунд экран возвращается к списку.
2. **Особые отметки** — с комментарием:
   - «Надевание» — пришла раньше на надевание невесты (отмечается приход);
   - «Фотосессия» — пришла раньше помочь невесте на фотосессии (отмечается приход);
   - «Переработка» — задержалась после конца рабочего дня (отмечается уход);
   - «Неполный день» — пришла позже или ушла раньше.
   Правила: «Надевание» и «Фотосессия» — сколько угодно раз за день; «Переработка» — один раз и только когда сотрудница на работе; «Неполный день» — один раз; «Неполный день» и «Переработка» в один день не ставятся. После ухода все кнопки неактивны — время правит администратор. Выходной, поставленный администратором, сотрудница сама не отменяет.
   Отметки сохраняются в табеле дня; в отчётах владельца рядом со временем будут буквы Н / Ф / П.
3. Отметки сразу видны владельцу и администратору в CRM → «Табель».
4. **Режим администратора** (кнопка внизу, пароль администратора или владельца):
   - «Выходные» — поставить выходной за сотрудника на один или несколько дней, не дальше двух месяцев вперёд, с причиной; отменить выходной. День, где сотрудница уже отметила приход, не меняется — она отмечает «Неполный день».
   - «Не отметили уход» — кто пришёл, но не нажал «Ушла» за последние 7 дней; администратор ставит время ухода.
   - «Фото» — снимки фронтальной камеры при каждой отметке (кто на самом деле нажал кнопку), по дням. Здесь же выключатель «Фото при отметке»: выключили — табель работает как раньше, без камеры. Если камера недоступна, отметка сохраняется без фото с пометкой.
   - «Сотрудники» — добавить нового (имя, логин, пароль) и удалить консультанта; его невест можно передать другому консультанту.
   - Закрывается сам через 2 минуты без касаний.

## Запуск

```bash
npm install
npm run dev
```

## Рабочая версия

Общая база PostgreSQL на российском сервере (152-ФЗ, паспортные данные), пароли в виде хэша, фото на сервере, печать договоров на залог и аренду из записи.
